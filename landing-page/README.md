# Learning Library (the site being measured)

A searchable library of 55 resources (courses, datasets, tools and templates, resources) for data, marketing and AI, with filters, a "Tools made by Zoe" band and a row of popular newsletter posts. Plain HTML, CSS and vanilla JS. It exists because Substack allows no custom tracking code: this is the site where the Data Layer and custom events are fully under my control.

**Live:** <https://tuhoang3112.github.io/zoe-learning-library/>

```text
landing-page/
├── index.html
├── css/styles.css
├── js/
│   ├── config.js        site URL, topics, types, levels (single source of truth)
│   ├── analytics.js     the only place where events are defined and pushed to the Data Layer
│   ├── app.js           renders the catalogue and the page
│   ├── filters.js       filters
│   └── search.js        search
├── data/
│   ├── resources.json   the catalogue
│   └── posts.json       popular newsletter posts
├── assets/images/       logo and covers
├── sitemap.xml, robots.txt   generated by ../scripts/build-seo.mjs
```

## Run it locally

```bash
cd landing-page
python -m http.server 8000      # or: npx serve .
```

Open <http://localhost:8000>. The page loads `data/resources.json` with `fetch`, so it cannot be opened from the file system directly. Tag Manager does not load on `localhost`; add `?gtm=on` to the URL to test tracking on purpose.

To regenerate the sitemap, canonical tags and structured data after changing the URL or the catalogue: `node scripts/build-seo.mjs` (from the repository root).

## Deployment

Pushing to `main` deploys this folder to GitHub Pages with GitHub Actions ([`../.github/workflows/deploy.yml`](../.github/workflows/deploy.yml)). Changes to the Tag Manager containers are published from Tag Manager itself, not from this repository.
