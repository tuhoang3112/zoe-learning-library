# SEO & Search Console

## What is implemented

- Semantic HTML (`header`, `nav`, `main`, `section`, `footer`, `h1`/`h2`), unique `<title>` and meta description per page
- Canonical URL on every page
- `sitemap.xml` (home page) and `robots.txt` (allows everything, points to the sitemap)

## Known V1 limitation

Resource cards link straight to the external site, so there are no per-resource pages to index; only the home page is in the sitemap. If SEO for individual resources becomes a goal, generate one static page per resource from `resources.json` and add them to the sitemap.

## Setting the site URL

1. Set `SITE_URL` in `landing-page/js/config.js` to the real deployed URL (e.g. `https://<user>.github.io/zoe-learning-library/`).
2. Run `node scripts/build-seo.mjs` — regenerates `sitemap.xml`, `robots.txt` and the canonical / `og:url` tags.

Note: on a GitHub Pages project site (`user.github.io/repo/`) `robots.txt` is not read by crawlers because it is not at the domain root. It takes effect with a custom domain.

## Search Console verification

1. Add a URL-prefix property in Google Search Console.
2. Choose the **HTML tag** method and copy the token.
3. The site is verified through the Google Tag Manager container installed in `landing-page/index.html`, so no verification meta tag is needed (keep the GTM snippet on the page). If another method is ever needed, the HTML tag method works: add the meta tag with the real token, never a placeholder.
4. Submit `sitemap.xml`, then use URL inspection → Request indexing for the home page.

## Brand search (goal: rank for the site name)

The realistic goal is to appear first when someone searches for "Zoe's Learning Library", "Data & AI Library" or the name of the author. What supports this:

- `<title>`, meta description, `og:*` and `twitter:*` tags carry the site name and the alternative names ("Data & AI Library and Resources").
- JSON-LD in `landing-page/index.html`: `WebSite` (with `alternateName` values) and `Person` (with `sameAs` links to Substack, LinkedIn and GitHub) so search engines connect the site with the author's other profiles.
- JSON-LD `ItemList` of every resource, regenerated by `node scripts/build-seo.mjs`, so crawlers see the catalogue without running JavaScript.
- Backlinks (the strongest signal): link to the library from the Substack profile / posts, the LinkedIn profile ("Featured" and website field) and the GitHub repository homepage field, using the name "Zoe's Learning Library" as link text.

Search Console: add the URL-prefix property, verify, submit `sitemap.xml`, then use "URL inspection → Request indexing" for the home page.
